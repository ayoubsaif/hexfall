## ADDED Requirements

### Requirement: App icon set
The client SHALL ship icons derived from one source image, `apps/client/brand/icon.png` (the hex mountain artwork, square, transparent background), which SHALL NOT be served itself. The derived files SHALL be:
- `favicon.ico` with 16, 32 and 48 px images, and `icons/favicon-32.png`;
- `icons/apple-touch-icon.png`, 180×180, on an opaque background (iOS renders transparency as black);
- `icons/icon-192.png` and `icons/icon-512.png`, transparent, `purpose: "any"`;
- `icons/icon-maskable-512.png`, opaque background, artwork inside the central 80 % safe zone, `purpose: "maskable"`;
- `icons/badge-96.png`, 96×96, white silhouette on transparent, for the Android notification badge.

A script (`pnpm icons:build`) SHALL regenerate all of them from the source. The generated files SHALL be committed, so the normal build does not need the image tool.

#### Scenario: Regenerate after art change
- **WHEN** the source image changes and `pnpm icons:build` runs
- **THEN** every derived icon and the Open Graph image are rewritten at their listed sizes

#### Scenario: Source not shipped
- **WHEN** the client is built
- **THEN** `dist/` contains the derived icons and no copy of the 1000×1000 source

### Requirement: Web app manifest
The client SHALL serve `/manifest.webmanifest` with name "Hexfall", short name "Hexfall", `start_url` `/`, `scope` `/`, `display: "standalone"`, a background and theme color matching the app, and the 192, 512 and maskable icons. `index.html` SHALL link it.

#### Scenario: Installable
- **WHEN** the built app is opened in Chrome over HTTPS
- **THEN** the manifest loads without errors and lists the 192, 512 and maskable icons

### Requirement: Page metadata
`index.html` SHALL include: `<link rel="icon">` for `favicon.ico` and the 32 px PNG, `<link rel="apple-touch-icon">`, `<meta name="theme-color">`, `<meta name="description">` (one sentence describing the game), and the Open Graph tags `og:type` (`website`), `og:site_name`, `og:title`, `og:description`, `og:image` (1200×630 `og-image.png`, with `og:image:width`, `og:image:height`, `og:image:alt`) and the Twitter tags `twitter:card` (`summary_large_image`), `twitter:title`, `twitter:description`, `twitter:image`. When the build variable `VITE_SITE_URL` is set, `og:url`, `og:image`, `twitter:image` and `<link rel="canonical">` SHALL be absolute URLs on that origin; when it is not set, `og:url` and the canonical link SHALL be omitted and images SHALL use root-relative paths.

#### Scenario: Link preview
- **WHEN** the client is built with `VITE_SITE_URL=https://hexfall.example.com` and that URL is shared in a chat app
- **THEN** the preview shows the title "Hexfall", the description and `https://hexfall.example.com/og-image.png`

#### Scenario: Local build without site URL
- **WHEN** the client is built without `VITE_SITE_URL`
- **THEN** `index.html` has no `og:url` or canonical link and no unreplaced placeholder text

### Requirement: Open Graph image
`og-image.png` SHALL be 1200×630, under 300 KB, show the icon artwork and the word "Hexfall" on a background in the app's colors, and be generated by the same script as the icons.

#### Scenario: Size check
- **WHEN** the icon script finishes
- **THEN** `og-image.png` is exactly 1200×630 and smaller than 300 KB

### Requirement: Notification icons
Notifications (push and local) SHALL use `icons/icon-192.png` as `icon` and `icons/badge-96.png` as `badge`.

#### Scenario: Android notification
- **WHEN** a turn push is shown on Android
- **THEN** the status bar shows the white badge and the notification shows the hex icon
