## Context

See proposal.md for the bug. `DialogContent` is a fixed 380 px box (`w-[min(380px,calc(100%-32px))]`, 24 px padding) with brass corner plates; its body scrolls vertically. `DialogFooter` is `flex justify-end gap-2`, and `buttonVariants` sets `shrink-0 whitespace-nowrap`, so a footer wider than the body overflows to the left, which cannot be scrolled to. `GameMenu` in the same file already renders actions as a column of full-width `secondary` buttons with icon, label and hint. Gold HUD icons are 128 px WebPs in `public/ui/icons/`, loaded by `gameIcon(name)`. `tools/resource-icons-gen.mjs` already generates icons with the Gemini image API ("Nano Banana") and keys out a chroma-green background with sharp.

## Goals / Non-Goals

**Goals:**
- Every paused-notice action is visible and pressable at any language and width ≥ 320 px.
- The paused notice and the game menu share one row style.
- New icons match the existing gold set and can be regenerated by script.

**Non-Goals:**
- Redesigning the other dialogs beyond the `flex-wrap` safety net.
- Regenerating or restyling existing icons (`leave`, `flag`, `pause` stay as they are).
- Changing pause, resume, end or leave behaviour or their confirmations.

## Decisions

1. **Column of rows instead of a wrapping footer.** The notice drops `DialogFooter` and renders `<div className="mt-4 flex flex-col gap-2">` with one `Button` per action (`w-full justify-start`), the same markup as the `GameMenu` rows: icon, then a `flex-col` span with the label and a `text-xs` hint. *Alternative:* a wider dialog or a wrapping footer. Rejected: a wider dialog breaks again with longer labels or on phones, and a 2+1 wrap looks accidental. To keep the markup in one place, extract a small `ActionRow` component (icon, label, hint, plus the `Button` props) inside `GamePause.tsx` and use it in both `GameMenu` and `PausedNotice`.

2. **Hint text must wrap.** `buttonVariants` has `whitespace-nowrap`, which would keep a long hint on one line and make it overflow. Rows add `whitespace-normal h-auto py-2` and the hint span uses `text-left`. The existing `GameMenu` rows get the same fix through `ActionRow`.

3a. **Play another game keeps the seat.** `backToStart()` (game over) forgets the seat token, and on connect the session auto-resumes `seats.lastRoom()`. A new option `backToStart({ keepSeat: true })` instead clears only the last room (`seats.setLastRoom(null)`), then clears the URL room and the local stores and restarts the connection as before. The token stays, so the saved games list shows the paused room and "Continue" resumes it. *Alternative:* make the paused notice dismissable over the board. Rejected: the board is frozen while paused, so there is nothing to do there, and the connection would keep holding the seat. No server change: a seated player disconnecting from a paused room is already the documented "close the tab and come back later" path.

3. **Resume is primary, first.** For the host, Resume is the expected action, so it uses the default (dark leather) variant at the top. End and Leave are `secondary`. Play another game comes before Leave because it is the safe exit; Leave stays last because it cannot be undone.

4. **Hints.** End reuses `pause.endNowHint` ("The player with the most VP wins.") and Leave reuses `leave.hint`. A new key `pause.resumeHint` covers Resume:
   - en: "Everyone continues from where you left off."
   - es: "Todos siguen desde donde lo dejasteis."

   Play another game (`pause.playAnother` / `pause.playAnotherHint`):
   - en: "Play another game" / "Your seat stays saved; continue from Your games."
   - es: "Jugar otra partida" / "Tu asiento queda guardado; continúa desde Tus partidas."

5. **Icon generator.** `tools/hud-icons-gen.mjs` reuses `env`, `generate` and `keyOutGreen` exported from `resource-icons-gen.mjs`. It sends the icons that sit next to the new ones (`pause`, `flag`, `leave`, `endturn`) as style references with a style prompt matching the set as it really looks: flat cel-shaded, thick dark-brown outline, muted wood/parchment/brass palette, centered, flat #00FF00 background, no text. It writes 128 px WebP to `public/ui/icons/<name>.webp`. Flags: `--out DIR` to write candidates elsewhere for review, `--force` to overwrite, plus a list of names. Subjects:
   - `resume`: a wooden right-pointing play triangle, the same wood as the `pause` bars.
   - `end-game`: a small brass trophy cup on a wooden base (the game ends and a winner is named). An hourglass was rejected because `endturn` is already an hourglass, and it must not look like `flag` either.
   - `home`: a small cottage with a wooden door and a peaked roof (the start screen).

6. **Footer safety net.** `DialogFooter` becomes `mt-3 flex flex-wrap justify-end gap-2`. This changes nothing for footers that fit and makes too-wide footers wrap instead of hiding a button.

## Risks / Trade-offs

- [Gemini output drifts from the set's style] → Generate into `--out` first, review candidates next to the existing icons, and only then write into `public/ui/icons/`. Regenerate as needed.
- [The API call costs money and needs the user's key] → The script is run only after the user approves; the generated WebPs are committed, so builds never call the API.
- [The game menu could look different after the `ActionRow` change] → It is the same markup plus wrapping hints; check it visually alongside the paused notice.
- [`flex-wrap` changes other dialogs] → It only applies when a footer overflows, which is a bug in every case.

## Migration Plan

Client-only, ships with the next build; no data or protocol migration. Roll back by reverting the commit.
